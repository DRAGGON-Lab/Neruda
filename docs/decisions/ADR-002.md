# ADR-002: Native standalone toolchain compatibility investigation

Status: **proposed; compatibility evidence incomplete**. Date: 2026-11-27.
Parent: N1 epic #3; immediate task: N1.2, issue #2.

## Decision under evaluation

Evaluate Tectonic 0.17.0, support bundle `tlextras-2022.0r0`, and Biber 2.17
with expected biblatex 3.17 as one compatibility unit. These historical versions
are candidates, not accepted production requirements. Evaluate native macOS
x86_64, macOS arm64 and Linux x86_64 separately; support requires actual evidence.

Use isolated, explicitly provisioned native tools and project-local caches.
Authors receive versioned self-contained project snapshots. Docker, package
registries and a separate Neruda checkout are not required author dependencies.
Preserve scientific sources during upgrades and rollback. Keep shell escape off.

Native archives minimize new infrastructure and fit the approved author workflow.
A container would add a runtime dependency and cannot currently run locally
because the Docker daemon is unavailable. A separate shared checkout would make
project relocation depend on another directory. Neither alternative is selected.

## Conditions before acceptance

Require actual article, Beamer and handout builds, cold/warm/offline evidence,
archive and consumed bundle/font identities, resolved bibliography, all-page
inspection and independent build review. Record failures without switching
compiler or bibliography semantics. A blocked native platform remains blocked;
no support guarantee is inferred from an available release asset.

See [compatibility report](../n1-2-compatibility.md). Production scaffold/styles,
build interfaces and release support remain gated on acceptance of this ADR.

## PR #11 review amendment

Construct subprocess environments rather than inheriting the host; isolate
configuration and caches in preflight and compilation, disable Biber user config,
and request bundled fonts by filename. Export sanitized receipts/logs durably
under the experiment evidence directory; keep raw cache-validation receipts local.

Native arm64 archive inspection succeeded, but Biber 2.17's universal loader is
blocked by this host's unsupported lipo `-extract_family` option. Compilation and
page review did not run. The upstream texlive2024-0312 bundle recipe is the
bounded alternative under investigation with Tectonic 0.17.0; its actual biblatex
version must determine the matching Biber. Neither replacement adoption nor
support acceptance is authorized by recipe availability. See the report for
identities, limitations and remaining provisioning/review gates.

## Manual arm64 thinning candidate

A separately provisioned Biber 2.17 arm64 slice, extracted using the installed
`/usr/bin/lipo -thin arm64`, passes the isolated exact-version check without
Rosetta, recompilation or bibliography-version changes. Original tools and failed
evidence remain intact. Consider this a candidate native provisioning strategy;
do not automatically thin binaries in the build runner.

The derived executable's signature verification fails, and publisher checksum
corroboration remains absent. No signatures or system protections were changed.
Native cold builds now reach the pinned bundle but fail with HTTP 429. Acceptance
still requires bibliography processing, cache characterization, consumed font/
bundle identity, all-page inspection and independent review. See the report and
tracked provisioning receipt for exact identities and commands.
