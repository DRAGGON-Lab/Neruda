# ADR-001: Extract reusable LaTexProjects infrastructure into standalone Neruda

**Status:** conceptual direction accepted (Design v0.1 decisions 1.5, 8.1-8.4, 10.1); proposed migration approach pending N1.1 review. Compatibility/distribution decision pending N1.2. Date: 2026-11-26.

The extraction and ownership decision remains in force. The historical Tectonic
preference below was a candidate. [ADR-003](ADR-003.md) records the current
MacTeX-first implementation direction and split native/portability gates.

## Context

LaTexProjects already documents semantic styles, paper/Beamer starters, a pinned Tectonic/Biber compatibility unit, Makefile/scripts and evidence conventions. It also includes working manuscripts, slides, teaching materials, generated artifacts, third-party material and host-/course-specific assumptions. Neruda must remain independently usable without AI and prevent research artifacts from becoming infrastructure dependencies. The target repository is greenfield.

Read the pinned [extraction inventory](../../upstream/LaTexProjects.md) before selecting assets. Static inspection established candidates and several portability blockers; no assets have been copied and no builds have been performed for Neruda.

## Decision

Selectively extract and adapt cleared reusable styles, minimal article/16:9 Beamer templates, toolchain pins and safe build/scaffold/check mechanics into Neruda. Keep LaTexProjects intact. New document projects own source, evidence and bibliography; Neruda provides independently versioned infrastructure, not a manuscript monorepo. Replace host-/course-specific assumptions, review licensing per component and use synthetic examples. Optional ANDES workflows reference a versioned evidence interface; they do not become a standalone build dependency. Prefer Tectonic for everyday lab builds and pinned compatible bibliography tools, subject to N1.2 clean-environment validation; support target-publisher class/engine overrides by reviewed adaptation.

## Options considered

| Option | Benefits | Costs / risks |
|---|---|---|
| Rename or wholesale fork LaTexProjects | Fast access to all assets and existing structure | Copies unrelated research/teaching, binary/cache assumptions and permissions; couples infrastructure to document history |
| Rewrite from scratch | Clean boundaries and no legacy code dependence | Loses established styles, mathematical/authoring conventions and valuable tested patterns; extra effort |
| Selective extraction with provenance (selected) | Preserve useful work while isolating infrastructure; explicit ownership, terms and migration | Requires inventory, adaptation and actual compatibility validation |
| Keep templates only as a submodule of the old research repo | Reduces immediate refactoring | Hidden dependency on upstream repo layout, releases and working documents |

## Rationale and consequences

Separate reusable templates and deterministic tooling from scientific authorship, project data and agent runtime. Keep the original source intact; each candidate retains source revision/digest and original license notices. The migration is not a command to copy everything at once. Existing Tectonic 0.17.0/Biber 2.17 and the old bundle are evidence of prior pin choices, not validated current Neruda requirements. N1.2 will compare clean supported build environments and packaging alternatives, record actual versions/logs/checksums and finalize an implementation ADR. No new language, package registry, installer, container requirement or support matrix is selected here. The historical upstream repository name and layout cannot remain hidden runtime dependencies.

## Risks, validation and revisit

- Tool portability: upstream wrapper has host-local cache and workshop paths; checksum list covers Intel macOS only; script/CI behavior must be adapted and tested in clean environments, with missing-tool diagnostics and explicit install approval.
- Build integrity: verify compiler and bibliography versions, cache/bundle/font identities, safe paths/overwrite protection, no shell escape, unresolved references and all rendered pages; CI must not depend on course-specific tasks or leak private artifacts.
- Licensing and branding: review each selected asset, publisher and branding terms; preserve MIT and third-party notices, exclude uncertain content until clearance. No redistribution of tool binaries or research evidence by default.
- Evidence: A3.1/N2.1 specify stable project-owned references; synthetic paper and slide share figure/evidence chain without ANDES installed for standalone builds. Clearly distinguish example results from research data.

Revisit if clean standalone builds cannot be achieved with the selected compatibility approach, asset permissions prevent reuse, distribution is impractical, or documented publisher requirements require a separate toolchain. G0/G4 gate releases; failed checks stay visible. Use the next available ADR number for N1.2, not a silent replacement of this decision. No code, package, CI, upstream repo or target settings have been modified by this ADR.
