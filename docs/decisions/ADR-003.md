# ADR-003: Native TeX Live / LuaLaTeX candidate

Status: **direction approved for implementation; compatibility and support pending**.
Date: 2026-11-27. Supersedes no accepted compatibility result.

The maintainer selected validation plus a daily command-line interface, standard
MacTeX installation, a dated release policy and VS Code with LaTeX Workshop.
Texmaker is an optional frontend using the same command. Neither editor nor an
agent runtime is a compiler dependency.

Evaluate MacTeX `mactex-20260324.pkg` and TeX Live
`texlive2026-20260301.iso`. These names identify candidate media, not verified
downloads or proof of identical package snapshots. Verify published SHA-512,
installer/signature provenance and relevant shared resource revisions before
provisioning or adopting them. Record measured SHA-256 separately. If resources
differ, stop and propose an explicit correction rather than synchronizing silently.
Use LuaLaTeX and latexmk with the Biber/biblatex pair from that reviewed snapshot.
Do not carry Biber 2.17 into the new candidate automatically.

Read-only host inspection found `/usr/local/texlive/2020`, Intel-only luahbtex
and Biber, biblatex 3.14, and TeXShop 4.44. Package receipts identify MacTeX 2020.
This is not native arm64 evidence. Preserve the installation and all ADR-002
Tectonic evidence. These were pre-install observations; native results follow below.

Provision through standard distributions; compilation uses installed local
resources. There is no Neruda bundle service or automatic install/update/repair.
The candidate driver requires an explicitly reviewed lock. No fabricated live
lock is committed. A reference string in a lock is not proof of publisher trust.

Acceptance requires the article, presentation and handout on native macOS arm64,
Intel macOS and Linux x86_64; exact consumed package/font identities, resolved
bibliography, cold/warm/OS-enforced offline experiments and every-page review.
Cold means empty writable caches with a complete installed dependency tree;
missing dependencies are a separate negative test. A successful command alone
does not establish compatibility or byte-identical cross-platform PDFs.

The driver remains a candidate. Native consumed-input verification, page counts,
cache experiments and a copied standalone project have now been exercised.
Cross-platform provisioning and independent acceptance remain pending. Tectonic's
acceptance gate remains intact; its snapshots now exclude generated build trees
so the two experiments cannot contaminate each other.

The maintainer subsequently explicitly approved the prepared TeX Live-only
MacTeX installation with system default/path changes, conditional on checksum
and publisher-signature verification. See the exact command and exclusions in
[provisioning procedure](../mactex-provisioning.md). Compatibility acceptance and
publication remain separate; this approval is not a successful installation record.

## Native validation observations

The maintainer installed the verified TeX Live-only package; package receipts and
the selected 2026 tree confirm it. LuaHBTeX 1.24.0, latexmk 4.88 and biblatex 3.21
were observed. The installed universal Biber invokes unsupported
`lipo -extract_family`; startup fails both inside and outside the sandbox.

The maintainer separately approved `lipo -thin arm64` for this new executable.
The separate derived binary reports Biber 2.21 and completes the bibliographies.
Its invalid signature is recorded; no security control was bypassed and the
original remains unchanged. Explicit `--biber` or `NERUDA_BIBER` selection and the
lock's override hash prevent fallback to the broken universal loader.

TeX Live's `openout_any=p` rejects absolute font-cache writes without an explicit
output root. Run-local `TEXMFOUTPUT` fixes this; write policy and shell escape
remain restricted. The macOS arm64 matrix passed cold, sealed-cache warm,
OS-network-denied warm and OS-network-denied empty-cache compilation for all
three fixtures. HTTPS control/denial probes validate the network boundary.
Missing installed resources cause exit 2 before compilation. Every matrix PDF
was rendered and compared with visually inspected reference pages.

These are local compatibility results, not an accepted supported release.
Linux/Intel macOS, shared-resource equivalence with the proposed Linux ISO,
independent review and maintainer acceptance remain outstanding.

## Matching Linux source — 2026-11-28

The March 1 ISO is not the March 22 MacTeX package snapshot (among other changes,
geometry 5.9 versus 6.0 and latexmk 4.87 versus 4.88). Do not silently align or
upgrade the Mac installation. The TUG-documented dated tlnet archive for March 22
matches revisions/container checksums for all 4,478 installed packages with shared
runtime files. A prepared Ubuntu-only installer requires the official TeX Live
key, valid signatures and reviewed hashes before any code from that archive runs.

The maintainer explicitly approved publishing the changes on PR #11 and running
the prepared Ubuntu 24.04 workflow. It provisions only a new private work tree,
uses no apt/system TeX install, and requires exact shared resources and versions
before fixture builds. See [exact procedure](../texlive-linux-provisioning.md).
Local metadata comparison is not claimed as completed GPG authentication; CI must
establish that gate. Intel Mac and supported-release acceptance remain pending.

Tradeoff: a larger conventional installation replaces on-demand support-bundle
fetching. Versioned installed resources still need verification; installation
alone does not confer reproducibility. See [stack guide](../latex-stack.md).
